## Context

This is a retrofit: the code (Jekyll site + preview script) already shipped and is live at
jef2k85.github.io before any OpenSpec spec existed. Per the reconciling-spec-drift skill's
retrofit-gap guidance, requirements must be re-derived from the code's actual branches/behavior,
not from memory of the design conversation that produced it — so every requirement below traces to
a specific file.

## Goals / Non-Goals

**Goals:**
- Capture current shipped behavior of the profile page and local preview tooling as `ADDED
  Requirements`, accurately enough that future changes can be proposed as deltas against them.
- Encode the site-owner's explicit rule: the resume PDF and the on-page content must not
  contradict each other for any item both happen to mention.

**Non-Goals:**
- No code changes in this change.
- Not attempting to spec implementation-level details that aren't user/owner-visible behavior
  (e.g. exact CSS variable names) — specs describe observable behavior, not the stylesheet's
  internals.
- Not fixing any bugs found while reading the code (none were found) — this change is
  documentation-only.

## Decisions

- **Capability split: `profile-page` vs `local-preview`.** These are separated because one is
  live/user-facing (what a visitor to jef2k85.github.io sees) and the other is a dev-only tool
  never deployed or seen by site visitors. Splitting them lets future changes to one avoid
  touching the other's spec.
- **PDF-vs-site consistency as a `profile-page` requirement, not a separate capability.** The
  consistency rule only makes sense in the context of the page's content sections, so it's a
  requirement within `profile-page` rather than its own capability.
- **Resume PDF is documented as a content dependency, not regenerated by tooling.** Today there is
  no automated check or build step enforcing PDF/site consistency — it's a manual authoring
  discipline. The spec states the requirement as owner-facing behavior; enforcing it with tooling
  (e.g., a CI diff check) is out of scope for this change and would be its own future proposal.

## Risks / Trade-offs

- [Risk] The PDF/site consistency requirement is currently unenforced by any tooling, so it can
  silently drift again after this spec is written. → Mitigation: call this out explicitly as a
  "Current compliance gaps" note in the spec rather than overstating it as automatically enforced.
- [Risk] Retrofitting specs from a small, fast-moving personal project may over-formalize
  something that will keep changing shape. → Mitigation: keep both specs minimal, describing only
  what's observably true today.

## Migration Plan

1. Land delta specs for `profile-page` and `local-preview` in this change.
2. No code/deploy steps — archive promotes the delta specs straight into
   `openspec/specs/<capability>/spec.md`.
3. No rollback needed beyond reverting the archived spec files, since no code changes accompany
   this change.
